# Railway Deployment Guide

## 🚂 Deploy to Railway

### Quick Start

1. **Push to GitHub:**
   ```bash
   git add .
   git commit -m "Add Railway deployment config"
   git push origin main
   ```

2. **Deploy on Railway:**
   - Go to [railway.app](https://railway.app)
   - Click "New Project" → "Deploy from GitHub repo"
   - Select your repository
   - Railway will auto-detect and deploy

### Environment Variables

Set these in Railway Dashboard → Variables:

```env
FLASK_ENV=production
SECRET_KEY=<auto-generated-by-railway>
FLASK_HOST=0.0.0.0
DATABASE_URL=<leave-empty-for-sqlite-or-add-postgres>
DASH_DEBUG=False
```

### Database Options

#### Option 1: SQLite (Simple, Free)
- Leave `DATABASE_URL` empty
- Data persists in Railway volumes
- Good for testing/small projects

#### Option 2: PostgreSQL (Recommended for Production)
1. In Railway: "New" → "Database" → "Add PostgreSQL"
2. Railway auto-sets `DATABASE_URL`
3. Update `config.py` to handle Postgres (see below)

### Files Created

- ✅ `railway.toml` - Railway configuration
- ✅ `railway-build.sh` - Build script with DB initialization
- ✅ `init_db.py` - Database initialization and CSV import
- ✅ `gunicorn.conf.py` - Gunicorn config
- ✅ `wsgi.py` - WSGI entry point
- ✅ `requirements.txt` - Python dependencies
- ✅ `runtime.txt` - Python version

### Build Process

Railway automatically:
1. Detects Python project
2. Installs from `requirements.txt`
3. Runs `railway-build.sh` if present
4. Starts with command from `Procfile`

### Health Check

After deployment, test:
- `https://your-app.railway.app/` - Homepage
- `https://your-app.railway.app/health` - Health check endpoint
- `https://your-app.railway.app/products/` - Products page

### Troubleshooting

#### Check Logs
```bash
# View deployment logs in Railway dashboard
# Or use Railway CLI:
railway logs
```

#### Common Issues

**No products showing:**
- Check build logs for CSV import
- Verify `data/cosmetics.csv` is in repo

**Database errors:**
- SQLite path: Railway uses `/app` as working directory
- Check `DATABASE_URL` environment variable

**500 errors:**
- Check application logs in Railway dashboard
- Verify all environment variables are set

### Local Development

Works exactly the same:
```bash
source venv/bin/activate
python start.py
```

Access at: http://localhost:6969

### Migration from Render

Railway is simpler than Render:
- ✅ No render.yaml needed (uses railway.toml)
- ✅ Auto-detects Python projects
- ✅ Simpler environment variable management
- ✅ Better free tier (500 hours/month vs 750)

### Advantages of Railway

1. **Simpler setup** - Less configuration needed
2. **Better DX** - Nicer dashboard and CLI
3. **Auto-deploys** - From GitHub automatically
4. **Volumes** - Persistent storage for SQLite
5. **PostgreSQL** - Free database included
6. **No cold starts** - On paid plan

### Cost
