## 📋 Deployment Checklist

### Before Deploying to Render:

1. **Push all files to GitHub:**
   ```bash
   git add .
   git commit -m "Fix Render deployment configuration"
   git push origin main
   ```

2. **Verify these files exist:**
   - ✅ `wsgi.py` - WSGI entry point
   - ✅ `render.yaml` - Render configuration
   - ✅ `init_render_db.py` - Database initialization
   - ✅ `gunicorn.conf.py` - Gunicorn config
   - ✅ `requirements.txt` - Python dependencies
   - ✅ `runtime.txt` - Python version (3.11.0)
   - ✅ `cosmetics.csv` - Product data

3. **In Render Dashboard:**
   - Go to your service
   - Click "Manual Deploy" → "Clear build cache & deploy"
   - Watch the logs for any errors

## 🔍 How to Debug Render Errors

### Check Build Logs:
Look for these success indicators:
```
✅ pip install successful
✅ Database initialization complete
✅ Imported X products
```

### Check Deploy Logs:
Look for:
```
🚀 Starting Gunicorn server...
✅ Server is ready. Listening on 0.0.0.0:XXXXX
[INFO] Booting worker with pid: XXXXX
```

### Common Error Messages:

#### "ModuleNotFoundError"
**Cause:** Missing dependency in requirements.txt
**Fix:** Add the missing package to requirements.txt and redeploy

#### "FileNotFoundError: cosmetics.csv"
**Cause:** CSV file not in repository
**Fix:** Ensure cosmetics.csv is committed to git

#### "OperationalError: unable to open database"
**Cause:** Database path or permissions issue
**Fix:** Check DATABASE_URL in environment variables

#### "Worker timeout"
**Cause:** Application taking too long to start
**Fix:** Already set timeout to 120s in gunicorn config

## 🌐 Environment Variables on Render

These should be automatically set by render.yaml:
- `FLASK_ENV=production`
- `SECRET_KEY=<auto-generated>`
- `DATABASE_URL=sqlite:////opt/render/project/src/instance/cosmetics.db`

If not, manually add them in Render Dashboard → Environment.

## ⚠️ Known Limitations on Render Free Tier

1. **Database is ephemeral** - SQLite data is lost on sleep/restart
   - Solution: Upgrade to paid plan with PostgreSQL disk
   - Or: Accept that test data resets (products are re-imported from CSV)

2. **App sleeps after 15 min inactivity** - First request takes ~30s
   - Solution: Upgrade to paid plan for always-on

3. **512MB RAM limit** - Using 1 worker to stay within limit
   - Solution: Upgrade for more resources
